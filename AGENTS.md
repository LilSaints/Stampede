# Stampede development

[README.md](README.md) is for users; keep development notes here. The contract is [SPEC.md](docs/SPEC.md); release gates are in [V1_STATUS.md](docs/V1_STATUS.md); [V1_ACCEPTANCE.md](docs/V1_ACCEPTANCE.md) maps requirements to automated, real-backend and terminal evidence (live desktop acceptance is pending).

## Setup

```powershell
npm ci
npm run build
claude --plugin-dir C:\Dev\Stampede
```

The build produces self-contained CLI, workflow-worker and hook bundles plus the Windows helper; an installed plugin needs no development dependencies. `dist/` is ignored by Git.

The MCP server is declared in `.claude-plugin/plugin.json`. Do not also register it as a project server: `${CLAUDE_PLUGIN_ROOT}` and `${user_config.stampedeHome}` are resolved only by the plugin loader.

## Versioning

The version lives in `package.json`, `package-lock.json`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `src/hub/config.ts` and README.md. The build fails unless they agree. Bump it for every change that should reach an installed copy: `claude plugin update` compares versions only, so an unchanged version leaves the plugin cache stale. A new version also requires a hub restart, because the shim refuses a hub with a different version.

## Installing

Sessions run an installed copy, never this working tree: the `stampede` marketplace is the release folder `~/.claude/stampede-release`, which Claude Code reads in place. `npm run install-plugin` builds and copies the plugin there ([scripts/install.mjs](scripts/install.mjs); another folder as its argument or `STAMPEDE_RELEASE_DIR`). After a new version, once no run is active:

```powershell
npm run install-plugin
Start-Process node -ArgumentList "$HOME\.claude\stampede-release\dist\cli.js", hub, --restart -WindowStyle Hidden
```

then `/reload-plugins` (or restart) in each open session, whose shims otherwise stay blocked on the old version. Try unreleased changes with `claude --plugin-dir C:\Dev\Stampede` instead.

## Verification

```powershell
npm test
npm run check
claude plugin validate . --strict
claude plugin test .
node node_modules/typescript/bin/tsc -p tsconfig.mod.json
```

Core tests use fake backends and temporary repositories. The mod type check needs `.claude-plugin/types/`, which is generated by loading the plugin from this folder (`--plugin-dir`) with the installed Claude build and is ignored by Git, as are raw artifacts and local Claude settings. `spikes/` holds real-CLI qualification programs that consume normal model usage; results are in [spikes/RESULTS.md](spikes/RESULTS.md).

## Agent-message rules

The hook module ([hooks/stampede-ui.tsx](hooks/stampede-ui.tsx), `AGENT_COMMS`) adds the compact agent-to-agent message rules to the system prompt of any session that can delegate. Workers get the equivalent from the hub contract in `src/contract/prompts.ts`. Change both together.
